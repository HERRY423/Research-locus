# 研究设计卡、证据候选与九条规则

本地更新，基于 0.1.1；未发布，也未替换宿主已安装包。规则执行版本为 metadata-checks.v3。此前三条规则修复记录见 [上一轮记录](metadata-review.md)。

## 研究者如何使用

新建或修订论断时必须核对「研究设计卡」并勾选确认框。卡片不是要求编造完整答案：不能确认的项目明确保留 `NOT_DECLARED`。核心字段包括分析单位、独立生物重复数、扰动／干预与图表对应；「更多设计声明」包含六类扩展检查所需信息。声明为已知的重复数必须填写整数。

已有档案缺少字段时显示 NOT_DECLARED，不自动改写历史。运行检查后每个论断都有九项覆盖结果：风险、信息不足、未触发、不适用。NOT_DECLARED 不会被转换为 false；只有明确的适用性或范围声明才使相关规则不适用。必填确认表示用户核对了设计卡，不表示研究事实完整或已验证。

## 从证据提取候选

1. 在「证据文件」中选择相关文本，回到设计卡点击「从所选证据提取设计候选」。
2. 宿主 Agent 收到范围固定的 design 请求，报告进展，通过 `locus.extract_design` 获取字段契约，读取指定证据后提交候选。
3. 候选区显示原值、候选值、解释、逐字摘录和文件定位。默认不勾选任何字段。研究者逐项核对、勾选、写理由后确认；不勾选则全部驳回。
4. 只有采纳字段写入 metadata；未采纳项保持原值。输入变化使旧发现、决定及其他待确认候选过期，需重新检查。确认相同值或全部驳回也会结束提取等待。

已知候选必须引用所选资源中的原文。服务端验证范围、快照和摘录字节是否存在，不验证解释是否正确。未找到信息不证明材料没有该设计；缺失、歧义或冲突应提为 NOT_DECLARED 并解释。插件自身不调用模型 API，普通浏览器预览不能真实发起宿主 Agent 提取。

## 九条规则

| 模块 | 风险条件 | 主要适用领域 | 关键局限 |
| --- | --- | --- | --- |
| design.ts | 细胞单位或独立重复不足，却作队列／人群外推 | 实验生物学、组学、人群研究 | 不重算统计、独立性或层级模型 |
| causal.ts | 因果范围且声明无扰动 | 实验与观察性研究 | 其他因果识别设计需人工评估 |
| source.ts | 声明图表与源数据不匹配 | 使用图表的定量研究 | 不做图像或数据比对 |
| multiplicity.ts | 多重检验且未控制错误率 | 组学、多终点研究 | 不自动确定检验族或重算校正 |
| sample-size.ts | 明确声明未报告样本量与计数单位 | 定量实证研究 | 报告样本量不证明功效充分 |
| batch.ts | 存在批次效应／混杂但未在模型或设计中处理 | 组学、多批次实验 | 不检测实际效应，不保证完全混杂可校正 |
| correlation.ts | 仅关联证据，却声明因果范围或措辞 | 观察性研究、组学、流行病学 | 不自动理解正文，措辞与证据类型需确认 |
| threshold.ts | 看过分组结果后才定阈值 | 分组比较、标志物、预测研究 | 探索性选择不是自动判定不当行为 |
| leakage.ts | 验证数据参与训练、拟合或调参 | 预测模型与机器学习 | 不审计代码，嵌套验证需结合实现复核 |

每条报告带 disciplines、limitation、ruleVersion。六项新增检查不会通过文本关键词擅自断定设计；Agent 提取与研究者确认提供输入。规则没有执行科学分析，也不授予计算权限。

## 接口与持久化

`create_claim` / `revise_claim` 的可选 metadata 向后兼容：修订时省略保留原值；提供对象替换整张声明，`{}` 清空为未知。新 UI 保存完整设计卡，显式使用 NOT_DECLARED。16 个设计字段定义在 `src/design-fields.ts`，basis 为可选手填定位。拒绝非法类型、额外字段与图表适用性矛盾。

`locus.extract_design` 参数：sessionId、runId、expectedRevision、claimId、snapshotHash、resourceIds，及可选 candidates。不带 candidates 为只读准备；带候选为持久提交。必须匹配页面登记的 design 请求，资源集合必须相同；每个 runId 最多一组候选。服务重启后临时进展消失，但保存的候选可继续核对。

候选格式：`{field, value, rationale, evidence:[{resourceId,quote,locator}]}`。只接收已列字段；每字段一个候选，最多 16 项；已知值必须有至少一个逐字摘录，NOT_DECLARED 可以无摘录。每项至多 5 个引用。拒绝越界、过期、取消或暂停请求，不执行证据中的指令。

`propose_design` 仅由 Agent 提取通道提交，不改变输入快照；`confirm_design` 仅由研究者 UI 通道提交，selectedFields 指定采纳字段，空数组表示驳回。值从原候选读取，确认接口不接受替换值，需要更正时用设计卡修订。候选与确认保存在 designProposals 和事件中；回放保留摘录、前后值和理由。研究者身份仍为本地声明身份，非独立认证。

v1/v2 档案不做读时迁移。v2 解释器冻结在 `src/legacy/metadata-v2.ts`，旧报告照原版本校验；新检查执行 v3，旧规则意见及关联决定过期。不能把新规则套回旧报告。

## 如何扩展规则

新增 `src/rules/*.ts` 模块，导出 RuleDefinition：稳定 id、version、标题、严重程度、类别、disciplines、limitation 和纯 evaluate(claim)，在 `src/rules/index.ts` 显式注册。注册表支持注入替代规则集合并拒绝重复 ID；这是构建时扩展，不执行外部传入代码。新增字段同时更新 design-fields、校验和提取契约。

规则必须区分未知与否，测试风险、不适用、未触发和信息不足。改变规则语义时升级执行版本，保留旧解释器与兼容测试，不能改变已保存报告含义。当前支持 v2 与 v3 报告解释。

## 验收边界

本地检查覆盖 63 项自动测试：九条规则、候选不直接写入、部分确认、全部驳回、重复提交、原文缺失、越界引用、矛盾确认原子拒绝、暂停与过期、Agent 无确认权、进展、持久化和旧档案兼容。

浏览器使用独立合成会话，经真实 MCP 提交预设候选，再通过页面确认 15 项、保留 1 项未采纳。九条规则中八项风险、一项不适用；另一个全未知因果论断报告八项信息不足、一项不适用。未勾选卡片确认框时提交被阻止。候选是确定性测试输入，未声称宿主模型已实际提取。

隔离安装包验证包括九条规则、提取准备、候选提交、UI 确认和重启恢复。原生 ChatGPT 中真实模型的提取质量与侧栏交互仍需 [宿主验收](host-acceptance.md)。
