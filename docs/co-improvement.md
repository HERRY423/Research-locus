# 论断共同完善：关系、修订与补证

本地共审把「发现问题 → 提出可选择的修改 → 研究者采纳 → 补证 → 局部复核」接在同一条审计记录上。它记录科学判断的过程，不能自动证明科学结论。

## 论断关系与局部重审

在论断详情中选择两个已有论断、关系与理由。箭头从上游前提指向下游结论。

| 关系 | 含义 | 自动传播重审 |
| --- | --- | --- |
| `supports` 支持 | 研究者记录的支持关系，仍待证据核验 | 否 |
| `depends_on` 依赖 | 下游结论的成立依赖这个上游前提 | 是，沿依赖边传递 |
| `contradicts` 矛盾 | 两项论断存在需要检查的冲突 | 否 |

只有明确的依赖边决定局部重审范围；不能从「支持」自动推断必要依赖。可同时记录支持和依赖。自连接、重复关系和依赖循环会被拒绝，矛盾关系按无向关系去重。

修改上游论断的内容、范围、设计或证据，以及明确驳回上游论断时，其依赖后代标记为需要重审。改变依赖关系也会使受影响的下游上下文需要重审。无关论断的有效意见、研究者决定与报告保留。旧意见和旧快照仍可回看，不把历史改写为当前意见。

「驳回论断」是独立操作；「驳回建议」仅表示不接受一条审查意见，不能由此推断论断被驳回。完成局部复核后，研究者填写理由确认已处理；这个操作不恢复历史意见、不认可科学有效性、不提升证据等级。

## 结构化修订提案

宿主 Agent 可以在 `locus.submit_finding` 中附加：

```json
{
  "revisionProposal": {
    "text": "在本研究样本中观察到 X 与 Y 相关。",
    "scope": "sample",
    "evidenceNeeds": [
      {
        "id": "donor-analysis",
        "category": "replication",
        "description": "补充独立供体层面的效应估计、区间及敏感性分析。"
      }
    ]
  }
}
```

三个部分均可省略，但整个提案不能空。`scope` 是 `sample`、`cohort`、`population` 或 `causal`。补证清单最多 20 项，ID 是 1–80 位字母、数字、下划线或连字符；类别为 `source`、`design`、`analysis`、`replication`、`causal`、`provenance`、`validation`、`other`。类别用于组织计划，不是科学评分。

页面不预选采纳项。研究者可只改范围、保留文字，或只把其中几项加入补证计划；之后可继续采纳同一提案剩余项。同一项不能重复采纳。相关论断或依赖被其他操作改动后，旧提案不能直接继续应用；应重新审查并提出新版本。Agent 不能通过提交建议直接修改论断。

每次采纳都保存所选项、理由和输入快照。补证项保留来源 finding ID，可由意见回到提案，再回到采纳记录。未勾选的文字、范围与证据项保持原状。

## 每条论断的缺失证据清单

清单由四部分组成：适用范围对应的基础材料、规则发现的缺口、研究者采纳的补证建议、待复核的上游依赖。基础材料包括原始来源、研究设计、分析与不确定性；队列或人群结论增加独立重复与外推依据，因果结论增加因果识别与替代解释。

研究者可以把已经关联到本论断的文件对应到具体补证项，并记录理由。文件关联仅表示「已提供，待核验」；声明仅表示「已声明」，不会变成「证据已验证」。论断或其依赖变化后，旧材料对应关系提示需要重新确认。

`NOT_ASSESSED` 仍是本版本的科学证据上限。清单回答进入科学评估前还缺哪些材料和工作，不承诺完成这些项就能升级。科学评估仍需要适合学科的标准、明确的结论范围和有资格的研究人员。

## 接口与持久化

- UI 操作：`add_claim_relation`、`remove_claim_relation`、`set_claim_disposition`、`acknowledge_re_review`、`apply_revision_proposal`、`link_evidence_requirement`。均由研究者界面发起，保留版本冲突与渠道限制。
- `locus.state` 的精简状态包含派生 `evidencePlans`；附件正文仍需显式读取。派生清单不改写历史档案。
- 当前材料快照仍为会话级摘要；意见是否继续适用按各论断及依赖上下文判断。新回调仍须携带最新版本和快照。
- 旧版档案不在读取时迁移或重算哈希；关系、采纳与补证对应关系使用可选字段向后兼容。

## 验收边界

自动测试和本地合成页面验收覆盖操作与状态变化；隔离安装包测试覆盖打包后的协议与重启恢复。真实 ChatGPT 宿主的消息投递、模型建议质量与科研使用效果仍需独立验收。

本次本地验收：79 项自动测试通过；浏览器实测 A→B→C 依赖链、D 仅有支持关系，缩小 A 范围后 B/C 重新标记而 D 保持原状态。先采纳范围和一项补证、后采纳文字，未选建议保留；材料关联后仍显示待核验。页面输入为明确标记的合成场景，不代表实际模型审稿或真实科研效果。
