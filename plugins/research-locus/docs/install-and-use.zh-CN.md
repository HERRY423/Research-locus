# Research Locus：安装、侧边栏与科研使用教程

论断依赖图、逐项采纳修订建议、缺失证据清单与局部重审的操作见 [共同完善闭环](co-improvement.md)。

导入 BioNexus 多供体差异表达 bundle、CSV／notebook 计算回执，以及分别检查 DOI 格式、注册记录和元数据，见 [计算证据与引用核验](computational-evidence.md)。计算导入不会执行代码；注册元数据一致不代表论文支持当前论断。

适用版本：0.1.1。面向支持本地 Git 插件市场、stdio MCP 和 OpenAI MCP Extensions 的桌面客户端。界面名称随版本与语言变化；本教程不能替代朋友实际客户端的安装验收。Web/手机不具备同等本地运行能力。

## 1. 安装前准备

安装 Node.js 22 或更新版本，在终端运行 `node --version` 确认。客户端需要能克隆 GitHub 仓库；如果添加市场时报找不到 Git，请安装 Git 后完全重启客户端。使用组织账户时，管理员可能限制自定义插件市场。

仓库已经包含完整预构建运行包。研究人员不用执行 npm install，不需要开发者的令牌，也不需要额外配置模型 API key。宿主模型的正常使用仍取决于用户自己的账户。

## 2. 按“添加插件市场”窗口安装

在桌面客户端打开 **插件 → 添加插件市场**，填写：

| 输入框 | 填写值 |
| --- | --- |
| 来源 | `HERRY423/Research-locus` |
| Git 引用 | `main` |
| 稀疏路径 | **留空** |

来源也可填写 `https://github.com/HERRY423/Research-locus.git`。不要填写 `blob/main` 网页链接、ZIP 地址、本地预览网址或 GitHub 令牌。

点击「添加市场」，进入 **Research Locus** 来源，找到 **Research Locus** 插件，点击安装并启用。添加市场只是登记来源，仍需安装插件。完全退出并重新打开客户端，再新建聊天。

不要将稀疏路径填写为 `plugins/codex` 或只填 `plugins/research-locus`：本项目的市场清单在仓库根下 `.agents/plugins/marketplace.json`，需要同时保留清单与插件目录。留空最稳妥。

如果用 CLI，同等的市场登记命令为：

```powershell
codex plugin marketplace add HERRY423/Research-locus --ref main
```

这一步仍需要回到插件目录安装并启用。支持范围与市场路径规则见 [官方打包文档](https://developers.openai.com/plugins/build/plugins)。

## 3. 在侧边栏打开，及如何固定

安装启用后，在宿主主导航／侧边栏查找 **Research Locus**，或悬停黑白圆环图标查看名称。点击它应打开独立的「项目 / 最近会话」首页；在桌面中宿主也可能显示配套对话和常驻应用页签。

入口配置是 `locus.open` 的 `_meta["openai/ui"].entrypoints: [{"type":"global"}]`，并提供透明背景 `currentColor` 图标。它是 [官方侧边栏应用机制](https://developers.openai.com/plugins/build/extensions)，与 Bits & Bolts 的全局入口属于同一类机制。

**固定是宿主操作：**如果当前客户端在该入口或插件详情的菜单中提供「固定 / Pin / 添加到侧边栏」，由用户选择它；如果入口已长期显示，则直接使用。如果没有此菜单，不要寻找插件内的“强制固定”开关：官方扩展规范没有让服务器强制 Pin 的 API。本项目也没有伪造固定成功。图标顺序、是否折叠、账号权限由宿主控制。

区分三处入口：

- 宿主主侧边栏 **Research Locus**：打开项目与历史会话首页。
- 会话中的 **Claim & Evidence Review**：在对话旁打开共审面板。
- 应用自己的左侧栏 **回放剧场**：查看该会话已记录的变化。

如果工具可用但主侧边栏没有入口，可在新聊天请求“打开 Research Locus 项目首页”，先检查服务是否启动；普通工具调用打开页面不能证明原生侧栏已成功加载。参照第 7 节排障。

## 4. 第一次使用：一个完整共审流程

1. **建项目与会话。** 首页点击「新建项目」，例如“论文论断复核”；选择项目后点击「新建会话」，例如“结果段落第一轮”。新会话为空白；预置合成示例仅供体验。
2. **提出论断。** 进入会话，在左侧点击「新建论断」。输入可被证据支持或反驳的具体表述，避免把研究问题直接写成结论。
3. **添加证据。** 选中论断后点击「添加文件」，支持 Markdown、TXT、CSV、JSON 文本，单文件最多 1 MB。当前不直接解析 PDF、Office、图像、FASTQ 或大型表达矩阵。将所需内容先转成带出处的文本；保留来源说明。
4. **选择上下文。** 在证据资源中勾选本次相关材料，并显式同步上下文。选择资源只是指定审阅对象，不授权后台开展新的科学计算。
5. **检查和审阅。** 点击「运行检查」获得限定的元数据规则意见；需要内容审查时，请宿主 Agent 根据选中的论断与资源提出有依据的 finding。规则检查不是论文核验，也不是模型独立复核。
6. **研究者介入。** 阅读理由与证据，在判断区质疑、驳回、暂缓或带限制接受，并写出理由。需要补充材料时可先暂停共审；暂停期间服务器拒收新的 reviewer finding。恢复后再继续。
7. **修订与重审。** 修改论断或补充证据后，旧意见与决定会过期但不会被覆盖。重新发起审查，避免旧快照上的“接受”被用于新材料。
8. **回放与导出。** 点击「回放剧场」，用上一步／下一步、时间线、进度条、播放／暂停回看。`−` 表示修改前、`+` 表示修改后。缺失快照显示“仅摘要”；回放不会撤销或重跑操作。从「更多操作 → 导出快照」保存完整 JSON。
9. **下次继续。** 返回项目首页，从最近会话进入原会话。程序重启后，已保存的本地会话仍保留。当前没有云同步、团队账户或多机自动合并。

可直接使用的宿主提示语：

> 打开 Research Locus 项目首页。我会新建会话并选择材料，先不要执行分析。

> 只审阅当前选中的论断与证据。区分原文依据、推断和缺失信息；用当前快照提交审阅发现，不替我填写研究者决定。

> 我已缩小论断范围，请重新读取当前版本，对照上一次发现复核，并保留尚未解决的证据缺口。

定向复核会请求宿主 Agent；请求发送不代表审阅已完成。BioNexus 适配器接收已经导出的多供体差异表达 bundle 与执行回执，不会自动启动 BioNexus 引擎或开展科学计算。

### 本地改进：让自己的论断进入内置检查

本地 v3 已升级为必须核对确认的「研究设计卡」，并增加九条规则与宿主候选提取。使用步骤见 [研究设计卡与候选确认](design-card.md)。以下基础字段仍然保留：统计分析单位、独立生物重复数、是否有扰动或干预、是否涉及图表与源数据对应、是否匹配，以及依据定位。只填已知信息；未知保留 NOT_DECLARED，细胞数不能代替独立个体数。选择“不涉及图表”会清除不适用的对应判断。

点击「运行检查」后，每个论断显示九条规则的结果：发现风险／信息不足／未触发／不适用。信息不足会展开缺失项与下一步；点击「补充审查信息」填写并说明修订理由，保存后重新检查。只修改这些信息也会让旧意见及决定过期，历史保留在回放中。没有风险不等于科学通过。

例如，范围为「人群」且分析单位为「细胞」会触发单位风险；因果论断明确填写没有干预会要求核对因果依据；图表明确不匹配会触发来源风险。未填写干预时显示“信息不足”，不会被当作没有干预。完整边界见 [内置检查说明](metadata-review.md)。此段描述本地更新，GitHub 及已安装包需另行更新才具备这些功能。

## 5. 数据、更新与退出

Windows 默认数据在 `%LOCALAPPDATA%\ResearchLocus\`；macOS 在 `~/Library/Application Support/ResearchLocus/`；Linux 在 `$XDG_DATA_HOME/ResearchLocus/`，未设置时为 `~/.local/share/ResearchLocus/`。`state.json` 为初始示例档案，`catalog/` 保存项目及独立会话。升级前备份整个目录。

`LOCUS_DATA_DIR` 可指定独立数据目录；高级 `LOCUS_STATE_PATH` / `LOCUS_CATALOG_DIR` 设置优先。每个数据目录只应运行一个服务进程，切换插件与本地预览时先关闭原进程。多宿主同时连接需要各自数据目录，当前没有跨进程写锁保证。

刷新市场／更新插件后重启客户端。CLI 可运行 `codex plugin marketplace upgrade research-locus` 刷新来源，再在目录确认插件已更新。固定 `main` 会跟随主分支；需要固定复现实验环境时，把 Git 引用改成你已验证的完整提交 SHA，并另存数据快照。

导出的档案可能包含导入文本，分享前请由研究人员检查内容。原型内的研究者身份是自报记录，并非认证签名；接受建议不会提升证据等级。

## 6. 无宿主时预览

下载或克隆仓库，在根目录执行：

```powershell
node plugins/research-locus/scripts/launch.mjs --http
```

保持终端运行，浏览器打开 `http://127.0.0.1:4317`。Ctrl+C 停止。端口占用时可先在 PowerShell 设置 `$env:PORT='4319'`，再启动并访问 4319。此方式只证明本地网页可运行，不等于安装进 ChatGPT。

## 7. 常见问题与首次验收

| 现象 | 检查方式 |
| --- | --- |
| 添加市场失败 | 来源拼写、Git 引用 `main`、稀疏路径留空、GitHub 网络与 Git 可用性；私有仓库还需要读权限 |
| 市场存在但没有插件 | 确认已刷新来源并进入 Research Locus 市场；根清单必须与插件子目录同时存在 |
| 安装后服务起不来 | `node --version` 至少 22，完全退出后重启；宿主 PATH 必须能找到 Node |
| 找不到构建文件 | 检查安装的是完整 `plugins/research-locus`，不是仅复制 manifest；重新刷新市场并安装 |
| 只有工具，没有主侧栏图标 | 确认启用 MCP 服务且宿主支持 OpenAI global entrypoint；记录客户端版本、账户界面和脱敏错误；不要用普通 MCP 客户端替代验收 |
| 没有 Pin 菜单 | 使用已有全局入口；是否提供固定菜单由客户端控制，本插件没有强制固定能力 |
| 页面有了但原生文件入口没有 | 当前规范中这些文件能力依赖桌面宿主支持；普通网页预览不能验证它们 |
| 研究档案似乎消失 | 检查运行用户和数据目录环境变量，关闭重复服务；不要删除旧目录 |

首次安装依次确认：市场可发现 → 安装启用 → 工具可连接 → 全局入口可见 → 新建会话 → 添加测试论断 → 回放修改 → 重启后恢复。真实资源选取、原生文件写回、宿主上下文同步还需要单独测试。

目前工程验证不等于原生客户端已验收。此分发为桌面本地 Git 市场；没有公开远程 MCP 地址，没有提交到 OpenAI 公共目录，也不通过 GitHub Pages 部署后端。参阅 [官方连接流程](https://developers.openai.com/plugins/deploy/connect-chatgpt) 和 [固定版本规范](https://github.com/openai/mcp-extensions/blob/ca16cb3bc015baaa1b849082d8755bbef18770cb/docs/spec.md)。
